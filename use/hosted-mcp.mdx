Hosted MCP is available in the web app on Pro, Tucker, and Founder. It lets a compatible AI assistant read information you explicitly publish from personal brains and, with your permission, queue changes.

MCP stands for Model Context Protocol. Tokens start read-only. You can enable writes for a token and choose the personal brains it can change.

## Understand what you publish

MCP uses a separate plaintext copy hosted by Tuck. It does not give the assistant your vault key or direct access to the encrypted vault.

Publishing is off until you enable **Shape** for a personal brain. This publishes titles, short snippets, dates, tag and people names, and linked todo details from eligible thoughts in that brain. The choice applies to the brain, not individual thoughts.

Snippets contain up to 240 characters of readable text. A thought without text can use an attachment filename or a label such as Photo, Audio, or File as its snippet.

**Full text** is an additional choice for each published brain. Tuck stores up to 64,000 characters of each thought's text, returned in pages of up to 8,000 characters. Text beyond the stored limit is not available through MCP.

Attachments, including transcripts saved as separate attachments, are not included in the hosted copy and cannot be read through MCP. Text within a thought—including any transcript text—can still be shared in its snippet or, if enabled, its full text.

**Privacy:** Tuck can read the published copy. It is also exposed if someone gains access to the relevant server data, and it may be disclosed through legal process. Your connected assistant receives information through your token and handles that information under its own policies. Publish only brains you are comfortable making available this way.

Shared brains cannot be published, including brains nested inside a shared brain.

## Connect your assistant

1. Unlock your vault in the web app.
2. Open **Settings → Hosted MCP**.
3. Turn on **Shape** for each personal brain you want to publish.
4. Enable **Full text** only for brains whose thought text you want the assistant to read.
5. Enter a token label and choose **Create token**.
6. Choose **Copy token** and save it securely. Tuck shows the secret only once.
7. In your compatible MCP client, use the endpoint shown in Settings with Streamable HTTP and bearer-token authentication.

The endpoint on the main Tuck site is `https://tuckthis.app/api/mcp`. The authorization header is `Authorization: Bearer <your-token>`.

Use a client that supports this transport and authentication. A client requiring a different sign-in method may need an adapter or may not connect directly.

Each token can read the account's published brains. Creating another token does not create a separate brain selection.

## Keep the hosted copy current

The unlocked web app publishes when you opt in and as the vault is loaded or synced. The assistant reads the most recently published copy, including after you lock Tuck or close your laptop.

Open and unlock the web app when you need recent changes reflected. Publishing uses content fingerprints to avoid repeatedly uploading unchanged thoughts. A browser without a local publishing history compares hashes with the hosted copy first. An empty hosted brain still needs its initial content upload.

This release does not add an iOS publisher. Changes made elsewhere need to reach an unlocked web client before that client can publish them.

## Let your assistant help with the doing

In **Settings → Hosted MCP**, enable **Write** on the token you want to use and select its writable brains. Both the source and destination must be writable when moving a thought. Use `whoami` to check the token's current permissions.

Write selection limits changes, not reading. Every token can still read the account's published personal brains. Shared brains remain ineligible.

Your assistant can create, append, edit, move, and delete thoughts; manage linked todos; and create or rename tags, people, and personal brains. A brain created through MCP has **Shape** enabled and becomes writable by the creating token after it is sealed. Archiving a brain turns off its hosted publication and keeps it in the vault.

<Warning>
A successful write request means **queued**, not saved in the vault yet. Open Tuck in a visible browser tab and unlock it. Allow about **20 seconds after unlocking** for the next processing pass, plus time for sync and network requests. Until an unlocked device seals the change, it stays queued. Your assistant has not lost the note. It is waiting for you to open the door.
</Warning>

The server holds the queued command in plaintext. The unlocked device applies it and encrypts it into your vault. The MCP server does not receive your vault key or directly edit encrypted vault records.

Ask the assistant to check `get_write` using the original `requestId`. `queued` is still waiting; `sealed` means the device applied it; `discarded` means it was dropped; `failed` means it could not be applied. A deleted target can fail with `thought_missing`. New thought and brain IDs become available after sealing.

Keep the same `requestId` when retrying the same action. Sending a new ID can create a second action. Queued writes do not expire simply because your devices are locked.

## Find thoughts, todos, and changes

The assistant can list published brains, search and read thoughts, list todos, tags, and people, and inspect recent changes. Search can include this token's pending writes, marked `pending: true`; that does not mean they are sealed. `list_pending` shows queued writes for this token.

Todo results include stable IDs, status, due dates, and repeat schedules. Dismissed todos remain visible through MCP even though the app hides them. Date-only due filters use your account time zone, with UTC as the fallback when it is unset. Review your time zone in **Account** settings, especially if you travel.

Full-text replacement requires the revision returned by `read_thought`. Tuck rejects stale replacements and replacements when the body is withheld. Appending is available without publishing full text.

See the [tool and capture reference](/developers/hosted-mcp-tools) for arguments, date handling, and examples.

## Receive a notice when something changes

Each token can have its own webhook URL and signing secret. Add an HTTPS URL on the token's row in **Settings → Hosted MCP**, then save it. Webhooks send small change notices, not thought bodies. Use MCP to fetch the published information you need.

If you used the earlier account-level webhook setting, save a URL on the token you want to use. The old account URL is no longer a delivery destination.

See [MCP webhooks](/developers/hosted-mcp-webhooks) for all eight event names, signature verification, and connection testing.

## Reduce or stop access

- Turn off **Full text** to remove stored thought bodies while retaining Shape information, including snippets.
- Turn off **Shape** to delete that brain's hosted copy.
- Choose **Revoke** beside a token to prevent future access with that token.

Removing access does not recall data an assistant has already received. Losing paid feature access blocks MCP serving and new publishing, but is not the same as deleting the hosted copy.
